# Белокуриха — отдельная страница «Номера»

[Открыть демку](https://kirschmunk.github.io/Kurort-Food/belokurikha-room-catalog/)

Это самостоятельный каталог, **не слайдер для главной страницы**. Четыре карточки в ряд на компьютере, две на планшете, одна на телефоне. Без цен, собственной шапки, футера, переключателей и ссылки «Все номера». Прежние демки слайдера не изменены.

Фотография и название открывают описание, характеристики и галерею. Под каждой карточкой — отдельная кнопка «Забронировать». **Поп-ап бронирования не реализован и не подключён по заданию заказчика:** в демке кнопка не открывает окно, а передаёт событие для будущей интеграции. Она не отправляет данные и не создаёт бронь.

## Установка без сборки

1. Скачайте репозиторий через **Code → Download ZIP** или получите его через Git. Нужна только папка `belokurikha-room-catalog` целиком; остальные проекты из репозитория не требуются.
2. Разместите эту папку в `/upload/` сайта. Например, фотография должна открываться по адресу `/upload/belokurikha-room-catalog/assets/images/11978-preview.jpg`.
3. Создайте отдельную страницу в CMS, используя штатную шапку и футер санатория. Вставьте **содержимое `block.html`** в основную колонку `.wrapper`, вне `<?php … ?>`. Это фрагмент, без `<html>`, `<head>`, `<body>` и собственной шапки.
4. Если CMS удаляет подключения из содержимого, перенесите три `<link>` из `block.html` в `<head>` **после основных стилей сайта**: `base.css`, затем `photo.css`, затем `catalog.css`. Два `<script>` разместите в конце страницы в том же порядке: `rooms-data.js`, затем `catalog.js`. Сохраните `defer` и `data-rooms-base`. Сам `<section>…</section>` оставьте в контенте.
5. Страница уже содержит заголовок `<h1>Номера</h1>`. Отключите автоматический дублирующий заголовок CMS для этой страницы. Ширина блока — до 1200 px; внутри `.wrapper` дополнительные боковые отступы обнуляются.
6. Очистите кэш и проверьте карточки, фотографии, открытие/закрытие описаний и мобильную версию. **Не подключайте старый `belokurikha-rooms/rooms.js` к этому блоку**: у каталога собственный `catalog.js`, без слайдера. Не вставляйте рядом другой блок с идентификаторами `br-rooms-modal-title`.

Если каталог установки отличается, замените `/upload/belokurikha-room-catalog/` **во всём `block.html`**, включая `data-rooms-base`. Относительные пути внутри CSS и `rooms-data.js` менять не нужно. `index.html` — только самостоятельная демка; в шаблон его целиком не вставляйте.

## Подключение вашего поп-апа бронирования

Кнопка содержит `type="button"`, `data-book-room="11978"` и полное название в `data-room-title`. При нажатии возникает всплывающее DOM-событие **`belokurikha:book-room`**, в `event.detail` передаются `{id, title}`. ID — идентификатор записи исходного каталога, а **не гарантированный ID категории в системе бронирования**; при необходимости сопоставьте его со своими ID.

Добавьте обработчик в скрипт сайта и вызовите из него вашу существующую функцию открытия поп-апа:

```js
document.addEventListener('belokurikha:book-room', function (event) {
  const roomId = event.detail.id;
  const roomTitle = event.detail.title;
  // Здесь вызовите реальную функцию вашего сайта для открытия поп-апа.
  // roomTitle можно подставить в поле «Выбранный номер».
  // roomId используйте после сопоставления с ID системы бронирования.
});
```

Этот пример — точка подключения, а не готовое бронирование. Альтернатива: подключить штатный обработчик сайта к селектору `[data-book-room]`. Выберите один способ, чтобы не открывать два окна. Кнопка «Забронировать» не вызывает окно описания номера.

## Файлы и данные

- `index.html` — демка; `block.html` — готовый фрагмент для страницы.
- `base.css`, `photo.css` — сохранённое оформление; `catalog.css` — сетка и кнопки.
- `catalog.js` — описание, галерея, закрытие и событие бронирования; без карусели.
- `rooms-data.js`, `rooms-data.json` — все 18 записей с сохранёнными текстами и параметрами.
- `assets/` — все 18 точных превью, 89 фотографий галерей и два шрифта Acrom. Внешних библиотек, сборки, внешних шрифтов и загрузки фотографий с другого сайта нет.

Используется ранее согласованный снимок каталога от **30.10.2026**: объединение 14 путёвок и пяти периодов. Это витрина номерного фонда, а не проверка наличия на даты и не обещание доступности по каждой путёвке. Данные этой задачей не пересверялись. В записи 15992 нет подробного описания в источнике: в окне показаны доступные фотографии и характеристики, текст не придуман. Оснащение не выводится, как согласовано ранее.

Для пересборки из корня репозитория: `node tools/build-belokurikha-room-catalog.cjs`. Проверка: `node tools/check-belokurikha-room-catalog.cjs`. Установщику запускать их не требуется.
