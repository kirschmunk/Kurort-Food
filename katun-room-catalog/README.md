# Страница номеров санатория «Катунь»

[Открыть демку](https://kirschmunk.github.io/Kurort-Food/katun-room-catalog/)

Готовая самостоятельная страница: 11 категорий, 51 фотография, карточки в сетке, открываемые галереи и характеристики. Без цен, слайдера каталога, хедера, футера и всплывающей формы бронирования. Все изображения и шрифты находятся в этой папке; доступ к фотобанку для установки не нужен.

**Перед публикацией на основном сайте:** часть характеристик ещё не подтверждена заказчиком. Они не выдуманы и не показаны посетителю. Перечень — [DATA-TO-CONFIRM.md](DATA-TO-CONFIRM.md). Все 11 категорий включены по согласованию с заказчиком.

## Установка на сайт

1. Скопировать **всю папку `katun-room-catalog`** в `/upload/katun-room-catalog/` на сервере. Не менять вложенную структуру `assets/images/` и `assets/fonts/`.
2. В шаблоне нужной страницы, **между штатными хедером и футером**, вставить содержимое [block.html](block.html). Только один раз. Не вставлять `index.html` внутрь действующей страницы.
3. Готово: фотографии и названия открывают описание/галерею, стрелки и миниатюры переключают фотографии. Закрытие — крестик, Esc или клик по фону за окном. Кнопка «Забронировать» ведёт на штатную [страницу онлайн-бронирования «Катуни»](https://www.katun-san.ru/reservation/). Новую форму заявки этот блок не создаёт и никуда данные не отправляет.

Если страница собирается PHP-шаблоном, вместо ручного копирования HTML можно вывести фрагмент:

```php
<?php
echo file_get_contents($_SERVER['DOCUMENT_ROOT'] . '/upload/katun-room-catalog/block.html');
?>
```

Фрагмент уже подключает CSS и два JS-файла. jQuery, Bootstrap и другие библиотеки не нужны. PHP-пример не зависит от конкретной CMS; место вставки выбирается в её шаблоне контента.

### Если папка будет лежать по другому адресу

В `block.html` заменить **все** вхождения `/upload/katun-room-catalog/` на новый путь. В том числе `data-rooms-base` у `catalog.js` — по нему открываются фотографии в галереях. Относительные пути внутри `rooms-data.js` не менять.

## Что входит

| Файл | Назначение |
| --- | --- |
| `block.html` | Готовый HTML-фрагмент для вставки в сайт |
| `catalog.css` | Вся вёрстка, цвета, адаптивность и локальные шрифты |
| `catalog.js` | Открытие карточек, переключение фото, закрытие и возврат фокуса |
| `rooms-data.js` | Данные для браузера; подключается перед `catalog.js` |
| `rooms-data.json` | Редактируемые исходные данные и отметки для уточнения |
| `assets/` | Все 51 фото и два файла шрифта Acrom |
| `index.html` | Отдельная демка для просмотра, не фрагмент шаблона |
| `build.cjs` | Пересборка HTML и данных после правок, без установки пакетов |
| `photo-sources.json` | Привязка каждого изображения к исходной категории и контрольные суммы |

Изображения подготовлены для web: до 1600 × 1200 px, WebP. Это фотографии из переданного фотобанка, не заглушки. В каждой галерее 3–5 снимков. Обработка — изменение размера и сжатие, без дорисовки или изменения интерьера.

## Как дополнить характеристики

1. Исправить нужную запись в `rooms-data.json`.
2. Заполнить `area` (м²), `main`, `extra`, `description` и `specs`. `null` означает «не подтверждено», **не ноль**. Значение `0` использовать только при подтверждённом отсутствии дополнительных мест.
3. В папке выполнить:

```sh
node build.cjs
```

4. Загрузить обновлённые `index.html`, `block.html` и `rooms-data.js`; при изменении изображений — также соответствующие файлы из `assets/`.
5. При обновлении CSS/JS изменить `version` в `build.cjs`, повторить сборку и сбросить кеш сайта/CDN.

В рабочей странице служебные поля `sourceFolder`, `sourcePages` и `pending` не используются. Когда описание будет заполнено, карточка автоматически откроется в двухколоночном формате «галерея + описание». Пока описания нет, открывается более широкая галерея без пустой колонки и без сообщения «данные уточняются».

## Подключение своей формы позже — необязательно

Сейчас ссылка работает без собственного поп-апа. Категория **не выбирается автоматически** в системе онлайн-бронирования: внутренние идентификаторы её номеров не предоставлены.

Для будущей интеграции предусмотрено событие. Обработчик на сайте может отменить переход и открыть **ваш** интерфейс:

```js
document.addEventListener('katun:book-room', function (event) {
  event.preventDefault();
  const { id, title } = event.detail;
  // Здесь вызвать существующую функцию бронирования вашего сайта.
  // id — локальный ID карточки, НЕ ID номера в системе бронирования.
  // title — название выбранной категории.
});
```

Не добавлять этот пример без реального вызова формы: иначе переход будет отменён, а ничего не откроется.

## Проверка после установки

- На широком экране четыре карточки, на планшете две, на телефоне одна. Блок занимает ширину родительской колонки, максимум 1200 px; внутри `.wrapper` подстраивается под её ширину.
- Фото и названия кликабельны; нижняя кнопка бронирования работает независимо.
- Проверить первую и последнюю категории, все фотографии в открытом окне, Esc, крестик и прокрутку страницы после закрытия.
- Проверить, что браузер получает CSS, JS, фото и шрифты без 404.
- Префиксы классов `kt-rooms` / `kt-catalog` изолированы от блока «Белокурихи». Глобальные стили хедера и футера этот код не меняет. После добавления в действующий шаблон всё равно проверить влияние общих стилей сайта.
- У демки в `index.html` стоит `noindex,nofollow`. В `block.html` такого метатега нет; индексацией рабочей страницы управляет сайт.

## Проверка в репозитории

Из корня репозитория при установленном Playwright:

```sh
node tools/check-katun-room-catalog.cjs
```

Проверяются 11 категорий, локальные изображения, отсутствие выдуманных неизвестных параметров, 7 ширин экрана (320–1440 px), галереи, закрытие, фокус и событие бронирования. Для дополнительного запуска в WebKit установить его браузер Playwright и задать `TEST_WEBKIT=1`. Можно указать путь к установленному Chromium через `CHROMIUM_BINARY`.
